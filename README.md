# pipasila.ru — сайт бренда PIPA 🧢

Официальный сайт бренда **PIPA** — уличные кепки и шапки из Казани. Репозиторий содержит статический сайт на чистом **HTML/CSS/JavaScript** с акцентом на скорость, аккуратную типографику и базовую SEO-обвязку.

---

## 🏷️ О бренде

**PIPA** — уличный бренд головных уборов из Казани: кепки, шапки и аксессуары в городском стиле.

Цели сайта:
- представить бренд и коллекции;
- быстро и красиво показывать контент на мобильных устройствах;
- быть понятным для поисковых систем (robots/sitemap, корректные мета-теги).

Технологический принцип: **без тяжёлых фреймворков** — минимализм в коде, максимум контроля.

## 🚀 Установка (локальный запуск)

Сайт статический — сборка не требуется.

### Вариант 1: открыть файл напрямую

Можно открыть `index.html` в браузере, но часть вещей (например, `fetch` или некоторые пути) может работать иначе из-за ограничений `file://`.

### Вариант 2 (рекомендуется): поднять локальный сервер

**Python:**
```bash
python3 -m http.server 8080
```
Откройте: `http://localhost:8080`

**Node.js (если установлен):**
```bash
npx serve .
```

## 🗂️ Структура проекта

Точная структура может отличаться — ниже типовая схема для этого репозитория:

```text

│   └── main.js

│   ├── img/
│   └── fonts/
```

Рекомендации по поддержке структуры:
- изображения хранить в `assets/img/` и использовать понятные названия файлов;
- шрифты/подключения держать централизованно;
- не раздувать `main.js`: выносить модули/функции по смыслу, если проект растёт.

## 📦 Деплой (Timeweb + nginx + Cloudflare)

Ниже — практичный сценарий деплоя для статического сайта.

### 1) Подготовка на сервере

Обычно сайт размещается в директории вроде:
- `/var/www/pipasila.ru/`

Проверьте права и владельца директории (в зависимости от вашей схемы деплоя).

### 2) Обновление сайта

Самый простой подход:
- скопировать обновлённые файлы на сервер (rsync/scp/CI);
- перезагрузить nginx при необходимости (обычно не требуется для статических файлов).

Пример через `rsync` (локально → сервер):
```bash
rsync -av --delete ./ root@YOUR_SERVER:/var/www/pipasila.ru/
```

> ⚠️ Внимание: `--delete` удалит файлы на сервере, которых нет локально.

### 3) Конфиг nginx (пример)

Пример минимального server block для статического сайта:

```nginx
server {
    listen 80;
    server_name pipasila.ru www.pipasila.ru;

    root /var/www/pipasila.ru;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # Кеширование статических ассетов
    location ~* \.(css|js|png|jpg|jpeg|gif|svg|webp|ico|woff2?)$ {
        expires 30d;
        add_header Cache-Control "public, max-age=2592000";
    }
}
```

Если сайт **не SPA**, строку `try_files ... /index.html` можно упростить до `try_files $uri $uri/ =404;`.

### 4) HTTPS + Cloudflare

Типовая схема:
- в Cloudflare включить проксирование (orange cloud) и настроить SSL/TLS режим **Full** или **Full (strict)**;
- на сервере поднять сертификат (например, Let’s Encrypt) или использовать Cloudflare Origin Certificate;
- включить редирект HTTP → HTTPS.

### 5) SEO-файлы

Проверьте, что доступны:
- `https://pipasila.ru/robots.txt`
- `https://pipasila.ru/sitemap.xml`

И что ссылки/путь к sitemap прописаны корректно (часто прямо в `robots.txt`).
